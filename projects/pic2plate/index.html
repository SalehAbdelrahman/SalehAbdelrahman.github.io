Pic2Plate Recipe Generator

Open-vocabulary food perception that turns a photo of your groceries into meals.

Overview

Pic2Plate identifies the food in a photo of a fridge shelf, a grocery haul or a countertop, shows where each item is, and suggests recipes that use what’s there. The project began as a five-person ELEC 290 team project at Queen’s University: a Raspberry Pi 5 with a camera and a grocery classifier. Saleh later rebuilt the perception pipeline and the web app on his own. He measured where each design failed and replaced it, moving from a closed-vocabulary classifier, through a detect-then-classify pipeline, to a hybrid of a vision-language model and an open-vocabulary detector.

Contributions

  • Designed a two-stage perception pipeline. Claude (a vision-language model) returns a schema-constrained inventory of every food item, using package labels to identify packaged goods. OWLv2, an open-vocabulary detector, then localizes each item from a visual query that Claude writes for it.
  • Split OWLv2 into separate image and text passes, so the expensive image encoding runs while the API request is in flight. Checked that the split reproduces the full model’s scores (difference under 1e-5).
  • Built and benchmarked the earlier pipeline. It took COCO Faster R-CNN detections plus class-agnostic region proposals, classified each crop with a ResNet-18 (81 classes) fine-tuned with crop augmentation, and filtered the results with confidence-based voting whose thresholds were grid-searched on the validation split.
  • Wrote a reproducible evaluation harness. It composites 3-6 grocery photos at random positions and sizes into synthetic multi-item scenes, caches detector outputs so thresholds can be swept quickly, and reports ingredient-level precision and recall on a held-out test split.
  • Built the Flask web app: upload or camera capture, a detection viewer with per-item boxes, pantry-staple assumptions, diet filters, and recipe ranking by how few ingredients you’d need to buy. Without an API key, the app falls back to OWLv2 alone with a built-in food vocabulary.

Results

  • Detect-then-classify with crop fine-tuning raised multi-item recall from 2% to 80% (F1 from 0.04 to 0.80) over whole-image classification on a held-out synthetic-scene benchmark. Crop-augmented fine-tuning alone took F1 from 0.69 to 0.80.
  • On a real grocery haul, the closed-vocabulary design found only bananas and carrots, and labelled a wine bottle “eggplant” with 100% confidence. That analysis motivated the move to open-vocabulary perception.
  • With OWLv2 alone, the app already finds the eggs, mushrooms, cauliflower, lemons and greens the classic pipeline missed.

Technologies

Python, PyTorch, torchvision, Hugging Face Transformers (OWLv2), Faster R-CNN, ResNet-18, Claude API (vision, structured outputs), Flask, JavaScript, Playwright

Media

The Pic2Plate web app. Users upload photos or use their camera, and each photo is analysed for every food item it contains.

Clicking a photo opens the detection viewer, with one coloured box per item and the details the pipeline extracted for each.

The same photo through two pipelines. Left: the classic detect-then-classify pipeline (81-class ResNet-18), which finds two kinds of food and confidently mislabels a wine bottle. Right: the open-vocabulary OWLv2 detector, which finds most of the produce, the eggs and the dairy.

Detected ingredients can be edited before searching. Pantry staples such as salt, oils and spices are assumed by default, so recipes aren’t penalised for needing them.

Recipes are ranked by how many detected items they use, then by how few ingredients are still needed.
